# raytsystem — Руководство пользователя

## Что это такое

raytsystem — это **офис для AI-агентов**. Представь коворкинг: есть столы (агенты), инструменты (навыки), архив (база знаний) и менеджер (интерфейс), который всё координирует.

**Зачем нужно:** чтобы несколько AI-агентов работали вместе над одной задачей, не мешали друг другу и вели историю того что сделали.

---

## Быстрый старт

**Запуск приложения (Windows):**
```
Двойной клик по raytsystem-start.bat
```
Откроется браузер на `127.0.0.1:8765` — это панель управления.

**Первый запуск:** приложение автоматически собирает «кодовый граф» (карту кодовой базы). Это занимает ~5-7 минут. Потом кэшируется — следующие запуски быстрые.

**Если что-то не запускается:**
```
uv run raytsystem doctor
```
Покажет что в порядке, а что нет.

## Основные компоненты

### 1. Каталог — справочник

Каталог как **меню ресторана**. Он не готовит еду, но знает:
- Какие блюда (навыки) есть
- Кто из поваров (агентов) их умеет готовить
- Какие правила (инструкции) нужно соблюдать

Каталог сканирует папки `packs/`, `skills/`, `agents/` и собирает полную картину. Он **только читает** — ничего не меняет.

### 2. Навыки (Skills) — рецепты

Навык — это **пошаговая инструкция** что делать. Как рецепт в кулинарной книге.

**Пример навыка `ingest`** (добавление в базу знаний):
1. Прочитай файл
2. Проверь что это не секрет и не вирус
3. Определи тип (текст, код, документ)
4. Извлеки факты и связи
5. Сохрани в базу знаний
6. Проверь что всё записалось

**Где лежат:** папка `skills/`, каждый навык — отдельная папка с файлом `SKILL.md`.

**Технический термин:** CAS (Content-Addressable Storage) — способ хранения где каждый файл имеет уникальный «отпечаток» (хеш). Если кто-то попробует перезаписать файл не изменив содержимое — система это заметит. Как штрих-код на товаре: одинаковое содержимое = одинаковый штрих-код.

### 3. Агенты (Digital Employees) — сотрудники

Агент — это **виртуальный сотрудник** с определённой ролью:

| Агент | Роль | Что делает |
|-------|------|------------|
| Оркестратор | Менеджер | Делит задачи на части, распределяет между другими |
| Строитель | Разработчик | Пишет код, создаёт файлы |
| Ревьюер | Контролёр | Проверяет качество, ищет ошибки |
| Исследователь | Аналитик | Ищет информацию, сравнивает источники |
| Библиотекарь | Архивариус | Сортирует знания, поддерживает порядок |

**Как управлять:** агенты настраиваются через YAML-файлы в `packs/starter/agents/`. Сейчас все отключены (`enabled: false`). Чтобы включить — поменяй `enabled: true` в нужном файле.

**Технический термин:** Pydantic — библиотека Python которая проверяет данные. Как строгий секретарь: не примет заявку если неправильно заполнена. Каждый агент проходит через Pydantic-валидацию — если поле пропущено или неправильного типа, система откажется работать.

### 4. Исполнение (Execution) — работа

Когда агент берётся за задачу:
1. **Задача** (Task) — карточка на Kanban-доске (входящая → в работе → ревью → готово)
2. **Назначение** — задачу закрепляют за агентом
3. **Сессия** — агент начинает работать, открывает «стол» (workspace)
4. **Результат** — файлы, черновики, обновления в базе знаний

**Аналогия:** Как Jira/Asana, только исполнители — не люди, а AI-агенты.

### 5. База знаний (Knowledge) — архив

Это **библиотека компании** с проверенными фактами:

| Папка | Содержимое | Пример |
|-------|------------|--------|
| `claims/` | Проверенные утверждения | «raytsystem написан на Python 3.12» |
| `entities/` | Сущности | «AgentOrchestrator — менеджерский агент» |
| `graph.json` | Связи между фактами | «AgentOrchestrator → использует → run-review» |
| `documents/` | Документы | ADR-решения, руководства, заметки |

**Технический термин:** FTS5 (Full-Text Search 5) — встроенный в SQLite полнотекстовый поиск. Как Google, но внутри приложения. Ищет по всем документам за миллисекунды с ранжированием по релевантности (BM25 — алгоритм «что важнее то выше в выдаче»).

### 6. Кодовый граф (Code Graph) — карта кодовой базы

Это **схема метро** для кода. Показывает:
- Кто кого вызывает (модуль A → функция B)
- Какие тесты покрывают какой код
- Какие файлы связаны между собой

**Зачем:** когда ты спрашиваешь «где используется функция X?» — система смотрит в граф, а не перебирает все файлы. Быстро и точно.

**Почему первый запуск долгий:** нужно пройти по ~350 файлам и построить ~5500 узлов и ~23000 связей. Потом кэшируется.

## Как работает поток данных

```
Ты (пользователь)
    ↓ создаёшь задачу
Web UI (Kanban-доска)
    ↓ назначаешь агента
Оркестратор (агент)
    ↓ делегирует куски задач
Исполнители (строитель, ревьюер...)
    ↓ работают с кодом/знаниями
База знаний / Файлы / Кодовый граф
    ↓
Web UI (видишь результат)
```

## Веб-интерфейс

Открой `127.0.0.1:8765` в браузере.

| Раздел | Что видишь | Что можешь |
|--------|------------|------------|
| `/agents` | Список агентов + детали | Смотреть (пока read-only) |
| `/skills` | Навыки с поиском | Смотреть, редактировать, форкать |
| `/tasks` | Kanban-доска задач | Создавать, двигать, назначать |
| `/knowledge` | База знаний | Смотреть факты и связи |
| `/documents` | Документы | Читать, искать |

## OpenCode интеграция

OpenCode — это CLI-инструмент для работы с AI. raytsystem подключается к нему через:

1. **`AGENTS.md`** — файл-меню: какую операцию какой навык обрабатывает
2. **`.opencode/skills/`** — тонкие обёртки которые перенаправляют на полные инструкции

**Аналогия:** AGENTS.md как меню в ресторане. OpenCode (официант) читает меню и передаёт заказ повару (raytsystem навыку).

## Частые вопросы

**Q: Почему граф собирается 7 минут?**
A: Каждый из ~350 файлов обрабатывается отдельным subprocess-ом (~1сек). Потом кэшируется — следующий раз 5 секунд.

**Q: Как добавить нового агента?**
A: Создай YAML-файл в `packs/starter/agents/` и добавь ID в `packs/starter/pack.yaml`. Подробнее в README.

**Q: Как добавить навык?**
A: Создай папку `skills/<название>/SKILL.md` с YAML-шапкой и телом инструкции. Или форкни существующий через веб-интерфейс.

**Q: Почему все агенты отключены?**
A: Это безопасный режим по умолчанию. Включай по одному когда готов протестировать.

**Q: Что такое CAS?**
A: Content-Addressable Storage — хранение по «отпечатку». Файл = хеш-сумма содержимого. Нельзя тихо подменить — хеш изменится. Как штрих-код: товар тот же → штрих-код тот же.

**Q: Что такое FTS5?**
A: Полный текстовый поиск в SQLite. Как внутренний Google для базы знаний. Ищет по всем документам, сортирует по релевантности.

**Q: Что такое Pydantic?**
A: Библиотека Python которая проверяет типы и структуру данных. Как строгий бухгалтер: не примет отчёт без всех подписей.
